# Building a release

The manifest is the version source. These build tools are for maintainers;
end users do not need Python, Inno Setup or Apple's developer tools.

1. Update the manifest, user-visible version, activation text and release notes together.
2. Run `python -m unittest discover -s tests`.
3. On macOS run `python packaging/build.py --macos`; test with
   `python -m unittest discover -s packaging -p 'test_*.py'`.
4. On Windows, compile `packaging/windows/PrintableThreads.iss` with Inno Setup 6,
   passing `/DVersion=<manifest version>`, then run `packaging/windows/test-install.ps1`.
5. Push an annotated `v<manifest version>` tag. The release workflow builds on Mac
   and Windows, verifies installed payloads/backups, then publishes a prerelease
   with both installers, the ZIP and SHA256 hashes. Neither source code archives
   generated by GitHub nor historical files in `dist` are the native installer.

Workflow manual dispatch builds artifacts without creating a release. The current
release notes file is explicitly `docs/RELEASE-0.5.2.md`; update it for the next release.

The macOS PKG is script-only: it carries a clean copy of the add-in in its script
resources and installs into the signed-in console user's home. It refuses symlink
destinations and retains the previous folder. It requires a logged-in user and admin
authorization; it is not intended for unattended fleet or multi-user deployment.
The Windows EXE uses stable Inno Setup AppId and per-user install/uninstall registration.

## Signing before broad distribution

No signing secrets are committed or uploaded by this workflow. Current assets are
explicitly named `unsigned`. To produce trusted releases, add a separately reviewed
signing step **before** checksums and publishing:

- macOS: `productsign` with a Developer ID Installer identity; submit the signed
  PKG with `xcrun notarytool submit --wait` using a keychain profile; staple it with
  `xcrun stapler staple`; validate signature, notarization and Gatekeeper assessment.
- Windows: sign the installer and generated uninstaller through Inno Setup's
  `SignTool` / `SignedUninstaller` settings using a trusted code-signing identity
  and timestamp. Validate signatures before publishing. Signing the outer EXE
  alone does not sign its embedded uninstaller.

Use scoped CI secrets or an external signing service for credentials, never files
in the repository. Remove `unsigned` from download links only after successful signing
and verification. Current CI does not claim notarization or Windows signing.
